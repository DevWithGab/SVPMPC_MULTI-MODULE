# Sample import data — 10 members with a ₱1,000 balance

Two uploads, in this order. Both screens accept **`.csv` only** (`accept=".csv"`,
and the handler calls `FileReader.readAsText`) — the `.xlsx` copies are here so
you can read and edit the data in Excel, then **Save As → CSV UTF-8** before
uploading.

## Step 1 — create the members

**SuperAdmin → Bulk Upload** → `01-members-10.csv`

Columns match `handleBulkUpload` in `client/src/pages/SuperAdmin.jsx:346`:
`memberId, memberName, email, phoneNumber, barangay, address, beneficiaries,
dateOfBirth, gender`

`memberId` is optional in the importer, but it is set explicitly here
(`MEM-2026-0001` … `MEM-2026-0010`) so step 2 can target the same members.
Each row also gets a `modules: ['attendance', 'mortuary']` default from the UI,
so the members land in both modules.

Emails use the reserved `example.com` domain so the automatic credential email
(`sendBulkCredentials`) does not reach a real inbox. Swap in real addresses if
you want to receive the temporary passwords — the server prints them in the
response either way. Bulk SMS is disabled server-side.

## Step 2 — give each member the ₱1,000 balance

**Mortuary → Treasurer → Member Ledger → Bulk Upload** → `02-ledger-1000-balance.csv`

The SuperAdmin import has no balance field — `Member` has no balance column at
all. A balance is derived from the `Ledger` collection, so it has to come from a
credit entry. This file posts one `contribution` of `credit: 1000` per member,
which `bulkUploadLedger` (`server/modules/mortuary/controllers/ledgerController.js:146`)
turns into a running balance of 1,000.00 each.

Columns: `memberId, transactionDate, credit, debit, description,
transactionType, referenceId, paymentMethod`

Re-uploading this file is safe — the controller rejects duplicates on
(memberId, date, credit, debit, referenceId).

## Regenerating

These files were generated by a throwaway script; edit the CSVs directly, or
re-create them with any spreadsheet tool as long as the header row is unchanged.

# Expansion set — 50 more members with a ₱1,000 balance

`03-members-50.csv` and `04-ledger-1000-balance-50.csv` extend the set above to
60 members total. Same two screens, same column headers, same order — members
first, then the ledger.

## Step 3 — create the 50 additional members

**SuperAdmin → Bulk Upload** → `03-members-50.csv`

`memberId` runs `MEM-2026-0011` … `MEM-2026-0060`, continuing where
`01-members-10.csv` stops, so the two files can be uploaded together or
independently without colliding. Emails and phone numbers
(`09171234011` … `09171234060`) are likewise unique across both files.

Names, barangays, addresses and beneficiaries are Filipino. Birth years span
1963–1994 and gender alternates, so the set exercises age- and
gender-dependent logic rather than clustering on one profile.

Emails again use the reserved `example.com` domain, so `sendBulkCredentials`
does not reach a real inbox.

## Step 4 — give those 50 members the ₱1,000 balance

**Mortuary → Treasurer → Member Ledger → Bulk Upload** → `04-ledger-1000-balance-50.csv`

One `contribution` of `credit: 1000` per member, dated `2026-09-17`, with
receipt numbers `OR-2026-0011` … `OR-2026-0060`. Identical in shape to
`02-ledger-1000-balance.csv`, just for the new member IDs — the duplicate check
on (memberId, date, credit, debit, referenceId) keeps re-uploads safe, and the
two ledger files never overlap.

Edit the `credit` column if you want varied balances instead of a flat ₱1,000
across all 60 members.

## No `.xlsx` copies for these two

Both upload screens accept `.csv` only, and Excel opens a `.csv` directly —
these files are plain CSV, so edit and save them as CSV UTF-8.
